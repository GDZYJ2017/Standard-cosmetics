## 数据流向

```
用户操作
   │
   ├─ 1. 上传参考标准
   │     前端 → Railway → 保存到 /app/data/standards/
   │                        → SQLite 记录元数据
   │
   ├─ 2. 创建审查任务
   │     前端 → Railway → 保存初稿到 /app/data/uploads/
   │                        → 创建 ReviewTask 记录
   │                        → 后台启动审查
   │
   ├─ 3. AI 审查流程
   │     Railway → 解析文档 (PDF/DOCX)
   │              → 规则检查 (YAML 规则)
   │              → DeepSeek API (语义分析)
   │              → 生成审查报告
   │              → 保存到 /app/data/reports/
   │
   └─ 4. 查看报告
         前端 → Railway → 读取报告 JSON
                          → 返回给前端渲染
```

## 环境变量说明

### Railway (后端)

```env
# 必填
DEEPSEEK_API_KEY=sk-xxx        # DeepSeek API 密钥

# 可选（有默认值）
DEEPSEEK_BASE_URL=https://api.deepseek.com/v1
DEEPSEEK_MODEL=deepseek-chat
DEBUG=false
PORT=8000                       # Railway 自动注入
```

### Vercel (前端)

```env
# 可选（可通过 URL 参数覆盖）
VITE_API_URL=https://后端域名/api
```

## 扩展建议

当免费额度不够时：

### 方案 1: Railway 升级 ($5/月)
- 无限运行时间
- 5 GB 存储
- 优先支持

### 方案 2: 数据库迁移
- SQLite → PostgreSQL (Railway 提供)
- 更好的并发支持
- 自动备份

### 方案 3: 对象存储
- 文件迁移到 AWS S3 / Cloudflare R2
- 释放 Railway 存储空间
- 更好的文件访问性能

### 方案 4: 多实例部署
- Railway 部署多个后端实例
- Vercel 自动负载均衡
- 提高并发处理能力
